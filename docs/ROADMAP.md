# 学习路线

不要求一次部署完整平台。每阶段都需留下可解释的源码证据和可复现的动手结果；遇到基础知识缺口，补充相关 Java、Spring、SQL 或网络知识后回到主线。

| 阶段 | 核心问题 | 动手成果 | 验收条件 |
|---|---|---|---|
| 0 环境基线 | 用哪个版本？最小启动需要什么？ | 固定 commit、依赖清单、启动记录 | 从记录可重建环境；必要服务健康状态有证据 |
| 1 请求闭环 | 一次登录和用户查询怎样完成？ | 脱敏请求、调用链、断点或日志证据 | 能定位入口、认证授权、业务、数据访问和返回处理 |
| 2 工程结构 | 通用封装和业务模块如何配合？ | 依赖图、一个自己的小功能 | 能解释 DTO/VO/DO 等实际约定；正常和失败输入均验证 |
| 3 服务边界 | 何时跨服务，失败如何传播？ | 一个真实跨服务调用及失败实验 | 定位客户端与提供端，说明超时、错误传播和恢复行为 |
| 4 缓存与协调 | Redis 缓存、锁解决什么问题？ | 缓存变化与并发实验 | 观察更新/过期；说明锁范围、超时和重复执行局限 |
| 5 异步与调度 | 消息和任务为什么不直接同步执行？ | 一种队列方案或真实定时任务实验 | 有生产消费/执行证据；检查重试与重复处理，记录未覆盖项 |
| 6 可靠性 | 慢请求、依赖故障怎样发现和控制？ | 超时、限流或追踪实验 | 可定位失败路径；记录恢复结果与适用条件 |
| 7 综合练习 | 如何设计一个完整的小业务？ | 自选业务、接口、数据模型、实验报告 | 可运行且能解释关键设计；有权限、数据一致性与失败路径验证 |

## 第一个学习成果

完成登录并查询用户，画出“请求 → 网关 → 认证/权限 → 业务服务 → 数据库/缓存 → 返回”的实际链路。该链路是调查目标，具体组件位置需按所选版本验证，不预先假定认证一定发生在哪一层。

## 节奏与复盘

每次聚焦一个可回答的问题。阅读后至少进行一次定位或实验，记录意外现象。每完成一个阶段，回顾：现在能独立解释什么、还缺哪些证据、是否需要调整下一阶段。学习状态以 PROGRESS 为准。
